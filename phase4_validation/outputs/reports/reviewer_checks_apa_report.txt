3. CHECK 3: DOES HIT TESTING FAVOUR LARGE TARGETS?
--------------------------------------------------------------------------------

The hit-test rule takes the deepest visible node containing the click, breaking
ties on drawing order and then toward the smaller area, so its first choice is
the most specific target. When that node is not clickable, the rule climbs to
the nearest clickable ancestor, which is larger by construction. Three
quantities bear on the resulting bias: how often the fallback fired, whether
touched icon-like elements are larger than background ones, and whether RQ3
holds once fallback touches are removed. The steps table's
used_ancestor_fallback column records whether the final element was non-
clickable, not whether the fallback fired, so the fallback is reconstructed here
from node depths: a click used it exactly when its resolved node is not the
deepest visible node containing the click in the top window.

unseen app, unseen task) only for test episodes; training and validation
episodes carry no subsplit label. Table IV can therefore use only the test
episodes, while the RQ4 regression uses every episode. The subsplits also
overlap, so Table IV's rows sum to more than the number of distinct test

NOTES, ASSUMPTIONS AND LIMITATIONS
--------------------------------------------------------------------------------

Limitations
  1. Variant F treats any non-empty hint as an accessible name. Hints can be
     placeholders ('Enter text'), so this is an upper bound on what a screen
     reader would usefully announce, as the primary measure is a lower bound.
  2. The fallback flag is reconstructed from node depths, not read from the
     parse, because the parser's used_ancestor_fallback column records a non-
     clickable result instead. The reconstruction applies the parser's own rule
     to the stored nodes; the script stops if any resolved click contradicts it.
  3. The fallback-free RQ3 rows drop fallback touches from the touched set only.
     The background keeps elements of the same kind, mostly clickable wrappers
     of role 'other', so those rows bound the direction of any fallback bias
     rather than estimate a bias-free difference.
  4. AndroidControl app identity comes from resource-id packages. An app whose
     views carry no resource ids, or one that spans several packages, can be
     split across clusters, which would narrow the app-level interval slightly.
