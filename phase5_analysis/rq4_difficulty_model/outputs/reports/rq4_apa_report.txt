1. WHAT THIS ANALYSIS CAN AND CANNOT CLAIM
--------------------------------------------------------------------------------

AndroidControl contains human demonstrations, not agent rollouts. It carries no
per-episode agent success field, so 'does label density predict agent success'
cannot be answered from this dataset. The outcome used here is the number of
steps in the human demonstration, which indexes task difficulty rather than
agent accuracy. Any claim about agent performance must come from the ecological
subsplit analysis below, or from a separate corpus of agent rollouts.

3. CONTROLLING FOR SCREEN COMPLEXITY
--------------------------------------------------------------------------------

Busier screens carry both more elements and more unlabelled ones, so an
association between density and difficulty could be complexity in disguise. This
model enters element count alongside density.

4. MODELS 2 AND 3: MORE ADJUSTMENT, AND AN EXPOSURE FIXED BEFORE THE DEMONSTRATION
--------------------------------------------------------------------------------

Model 1 is the H4.2 model above. Model 2 adds AndroidControl's published split
(train, validation, test; train is the reference) and clusters standard errors
by app, the app being the dominant resource-id package of the episode
(a11ydebt/apps.py), with episodes that have none as their own cluster. The
element count in Models 1 and 2 is the total across the episode's screens, which
grows with the number of screens and so with the outcome. Model 3 therefore
takes both label density and element count from the episode's first in-app
screen: observation 1 when the first action is open_app (observation 0 is then
the screen the app was opened from), otherwise observation 0, the screen shown
before the first action. Episodes enter Model 3 only if that screen has at least
5 elements needing a label. Nothing in Model 3 depends on how the demonstration
unfolds. The number of screens visited is not entered: every AndroidControl step
carries one observation, so screens visited equals steps plus one and would
reproduce the outcome. The specification checks change one choice at a time:
Check A uses observation 0 with its own element count, Check B the first in-app
screen with the episode-total count, and Check D observation 0 with the episode-
total count. These are associations; none of them says that labelling changes
how long a task takes.

5. LABEL DENSITY ACROSS THE BENCHMARK'S SUBSPLITS
--------------------------------------------------------------------------------

AndroidControl's four test subsplits are designed to test different kinds of
distribution shift. They are NOT a partition: they overlap substantially, so
metrics must never be summed across them. If they also differ in label density,
then reported per-split accuracy differences partly reflect accessibility rather
than the shift each split was built to measure.

NOTES, ASSUMPTIONS AND LIMITATIONS
--------------------------------------------------------------------------------

Notes
  1. If agent rollouts become available, the same script takes an agent-success
     outcome by swapping the 'steps' column for a binary success column and the
     negative binomial for a logistic model.

Limitations
  1. The outcome is demonstration length, not agent success. AndroidControl
     contains human demonstrations and no agent rollouts, so no claim about
     agent accuracy can be made from the episode-level models here.
  2. Demonstration length is a coarse difficulty proxy. A long demonstration may
     reflect a complex goal rather than a hard interface, and label density is
     measured over the whole episode rather than at the moment of each decision.
  3. Models 1 and 2 adjust for the log of the total number of elements across an
     episode's screens. That total grows with the number of screens visited, so
     it partly measures the outcome, and the association they show should not be
     read as a finding. Model 3 takes density and element count from one screen
     fixed before the demonstration and is the specification to report.
  4. The subsplit analysis is ecological: it compares aggregate label density
     with aggregate published accuracy. An association at split level does not
     establish one at episode level.
